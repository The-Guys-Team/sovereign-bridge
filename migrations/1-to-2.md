# Migration 1 → 2: bring v5.0 Project docs into the four-tier files

**Who this is for:** a student who used Bridge v5.0, where their data lived as Project docs (Profile.md, Experience Inventory.md, Target Criteria.md, Mind Map.md, Network Tracker.md, Projects.md, Session Log.md) inside the Claude Project, and/or in a dashboard.

**Only with the student's okay.** This migration runs only after the student has agreed to it (kernel §7). If they haven't, or they change their mind partway, stop and leave their existing docs and files exactly as they are.

**Never drop information.** If something doesn't fit a column, put it in the row's `note` or in CORE under the closest heading.

1. Confirm with the student before starting: say which docs you found, that they'll be copied into the new format, and that the originals stay where they are. Go ahead only once they say yes.
2. Snapshot first. If Drive is connected (and the student agreed to it), copy any existing `Bridge/` files to `Bridge/_backup/` with today's date in the name. The v5.0 Project docs themselves stay untouched as the original copy.
3. Ask the student to make the old docs readable: they're in this Project's files already, or they can paste them. Read all seven if present. Don't ask them to reformat anything.
4. Build the files from the templates (kernel §1.4), fetched from the same version tag as the kernel. If Drive is connected, create them in the Drive `Bridge/` folder; if not, hold them in the conversation and finish by outputting the save-file (kernel §8), then make the optional Drive offer. Set `_META.schema_version` to 2 and `approved_version` to the current version.
5. Map:
   - **Profile.md** → CORE *Profile* and *Networks* (keep the "word vomit" close to verbatim).
   - **Experience Inventory.md** → CORE *Experience inventory* rows (one row per experience; assign `e-001`…).
   - **Target Criteria.md** → CORE *Target criteria*. Date the current hypothesis with the file's date, or today if unknown; note "imported".
   - **Mind Map.md** → CORE *Mind map*; pull bridge skills and the elevator pitch into *Bridge skills and elevator pitch*.
   - **Network Tracker.md** → ACTIVE *Contacts (open)*. Assign ids `c-001`…. Map Outreach Status to the status vocabulary in module 3. Contacts with status closed or no activity in 90+ days go to `archive/<month of last contact>.md` under *Closed contacts*.
   - **Projects.md** → ACTIVE *Projects (open)*; closed ones to the archive.
   - **Session Log.md** → ACTIVE *Recent log* for the last ~60 days; older entries to the matching `archive/YYYY-MM.md` *Log*.
   - Any dashboard collections that hold data missing from the docs (tasks, guidance, prep, interactions, opportunities): import them into the matching ACTIVE tables. Docs win when they disagree with the dashboard.
6. Show the student a short summary (counts per table, anything you weren't sure how to place) and ask them to correct anything wrong.
7. Let them know the new files (Drive folder, or the save-file) are now the record, and the old Project docs are still there as a backup. Whether to keep or remove them is their call; don't move or delete them yourself.
8. Run the size check. If a file is over budget, offer the rollup (kernel §6).
